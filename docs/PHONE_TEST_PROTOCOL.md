# بروتوكول اختبار الهاتف — خطوات حرفية (S22 Ultra)

**الهدف:** تثبيت PoC وقياسه وتسجيل النتائج. البناء يتم في مستودع
Tilawa-PoC المنفصل عبر `poc.yml` (طبقة lite أولاً، إصدار `poc-1`)، ثم
تُنفَّذ مصفوفة الـ 30 جلسة على S22 Ultra. لا دمج للمحرك في التطبيق
الرئيسي إطلاقاً قبل GO موثَّق.

## 0. قبل البدء — المتطلبات

- هاتف Samsung Galaxy S22 Ultra (8/12 GB RAM، arm64) + شاحن.
- APK من إصدار `poc-N` في مستودع **Tilawa-PoC المنفصل**
  (`github.com/ezzaldeenmansour123/Tilawa-PoC`) — يُبنى عبر
  `.github/workflows/poc.yml` بتشغيل يدوي `workflow_dispatch` — لا يُبنى
  على كل دفع. **ليس مستودع Tilawa ولا Tilawa-Pro.**
- نصوص مطبوعة للمقاطع المعلنة (الفاتحة، آية الكرسي، الإخلاص، الملك 1–5)
  مع الأخطاء المزروعة مكتوبة عليها — هذه هي الحقيقة الأرضية.
- ساعة إيقاف (أو هاتف ثانٍ) لقياس زمن تأكيد الخطأ الكامل.
- (اختياري) كمبيوتر فيه `adb` لقياس الذاكرة + سماعة بلوتوث.

### 0.1 قائمة تحقق قبل البدء (لا تبدأ الجلسات قبل إكمالها كلها)

- [ ] بطارية الهاتف ≥ 50% والشاحن قريب (جلسة البطارية 30 دقيقة قادمة).
- [ ] مساحة تخزين حرة ≥ 500 MB (النموذج 24.7 MB + المرجع 4.7 MB + ملفات WASM + السجلات).
- [ ] APK من إصدار `poc-N` مثبَّت، ويظهر باسم «Tilawa PoC» بجانب «تلاوة» دون أن يستبدله.
- [ ] إنترنت متاح **للتنزيل الأول فقط** (النموذج + المرجع + WASM) — ثم يُقطع في اختبار الطيران.
- [ ] بطاقة النموذج (§أ أدناه) تظهر «مثبَّت — جاهز» مع البصمة الصحيحة وحجم WASM غير صفر.
- [ ] إذن الميكروفون ممنوح (يُختبر الرفض لاحقاً في §و — لا ترفضه الآن).
- [ ] النصوص المطبوعة للمقاطع الأربعة جاهزة، وملف حقيقة أرضية JSON جاهز
      لكل جلسة مخططة (القالب: `test_data/ground_truth_example.json` —
      نفس `session_id` الذي سيظهر في اسم ملف JSONL المصدَّر).
- [ ] ساعة إيقاف جاهزة + دفتر نتائج (ورقي أو ملف) لتدوين كل جلسة حسب
      قالب التسجيل في §4.
- [ ] (اختياري) `adb` متصل ويعمل: `adb devices` يظهر الهاتف.

## 1. كيف يُبنى PoC

1. في GitHub: مستودع **Tilawa-PoC** → Actions → «Build Tilawa PoC APK» →
   Run workflow → اختر الطبقة `lite` (أولاً) → Run.
2. يمر سير العمل بمرحلتين:
   - **node-smoke**: يتحقق من واجهة المحرك الحقيقية (تحميل lite + جلسة
     صمت) قبل بناء أي APK — إن فشل، لا يُبنى APK ويُدوَّن السبب.
   - **build**: حزمة الويب + تنزيل الأصول مع تحقق SHA-256 + فحص مخطط
     المرجع + `flutter analyze` + `flutter test` + بناء APK (arm64 فقط).
3. الناتج: إصدار `poc-N` فيه `app-arm64-v8a-release.apk` + أثر (artifact).

## 2. كيف يُثبَّت

1. نزّل APK من إصدار `poc-N` على الهاتف.
2. ثبّته (قد يطلب السماح بالتثبيت من مصادر غير معروفة — هذا متوقع).
3. تأكد: التطبيق يظهر باسم **«Tilawa PoC»** ولا يستبدل تطبيق «تلاوة»
   المثبَّت (حزمة مختلفة: `com.tilawa.app.tilawa_poc`).
4. افتحه وامنح إذن الميكروفون عند الطلب.

## 3. ما الذي يختبره المستخدم — خطوة بخطوة

### أ. بطاقة النموذج (تبويب «النموذج»)
1. اختر `lite` ثم «تنزيل النموذج والتحقق منه» — هذا الزر ينزّل ثلاثة
   أشياء معاً: النموذج + المرجع `ref-v2.json` + ملفات تشغيل المحرك
   الأربعة (WASM). لا يكتمل التثبيت دونها كلها.
2. تأكد من: الحالة «مثبَّت — جاهز»، الإصدار `spliced-clean-lite@1-int8`،
   الحجم 24.7 MB، SHA مختصر `4974de78d3c3` (أول 12 حرفاً).
3. تأكد أيضاً من سطر «ملفات تشغيل المحرك (WASM)»: يجب أن يظهر حجماً
   غير صفر (4 ملفات، `ort/1.30.0/`). إن ظهر «غير منزَّلة بعد» رغم نجاح
   تنزيل النموذج، دوّن ذلك نصاً وأعد التنزيل؛ وإن تكرر، أوقف الاختبار
   هنا — فبدون WASM لن يبدأ المحرك إطلاقاً (يظهر خطأ واضح عند بدء
   التسميع). دوّن حجم WASM المقيس في تقرير النتائج (المعيار 9).
4. إن ظهر «فشل التحميل» مع سبب، دوّن السبب نصاً وأوقف الاختبار هنا.

### ب. اختبار التحميل البارد (المعيار 8) — 3 مرات
1. أغلق التطبيق تماماً (إزالته من قائمة التطبيقات الأخيرة).
2. افتحه، ابدأ جلسة، وسجّل زمن تحميل النموذج الظاهر في الشاشة.
3. كرر 3 مرات. العتبة: lite ≤ 15 ث.

### ج. جلسات المصفوفة (المعايير 1–6، 14)
لكل جلسة من الـ 30 (انظر `docs/MEASUREMENT_PLAN.md` §3):
1. اختر المقطع المعلن من القائمة.
2. ابدأ الجلسة، وتِلُ حسب النص المطبوع (بما فيه الخطأ المزروع، إن وُجد).
3. لاحظ: زمن ظهور أول تظليل (تقديرياً بالثواني)، وكل خطأ مؤكد يظهر.
4. عند الخطأ المزروع: شغّل ساعة الإيقاف لحظة نطقك الكلمة الخاطئة،
   وأوقفها لحظة ظهور التأكيد على الشاشة — دوّن الزمن (المعيار 2 الكامل).
5. أوقف الجلسة. صدّر السجل من تبويب «السجلات» (مشاركة ملف JSONL).
6. دوّن في دفتر النتائج: الأخطاء المؤكدة مقابل المزروعة، الإنذارات
   الكاذبة، وحالات «غير متأكد».

### د. قياس الذاكرة (المعيار 7)
1. من الكمبيوتر: `adb shell dumpsys meminfo com.tilawa.app.tilawa_poc`
   قبل الجلسة (خط الأساس)، ثم في الدقائق 5/10/15 من جلسة 15 دقيقة.
2. دوّن PSS والـ Peak. العتبة: زيادة lite ≤ 400 MB، صفر OOM.
3. بدون `adb`: استخدم Android Studio → Profiler، أو دوّن «لم يُقَس —
   يُعاد» (لا تُخترع رقماً).

### هـ. اختبار وضع الطيران (المعيار 10)
1. فعّل وضع الطيران، أعد تشغيل التطبيق، نفّذ جلسة كاملة.
2. يجب أن يعمل كل شيء دون أي خطأ تحميل. أي طلب شبكة أو فشل = فشل المعيار.

### و. اختبار رفض الإذن (المعيار 12)
1. من إعدادات النظام: امنع إذن الميكروفون عن Tilawa PoC.
2. افتح التسميع: يجب أن تظهر رسالة واضحة بلا تعطل.
3. أعد منح الإذن وتأكد أن التسميع يعمل مجدداً.

### ز. اختبار الاستقرار (المعيار 13)
1. 20 جلسة قصيرة متتالية (فتح/تسميع/إنهاء) بلا تعطل.
2. في إحداها: أخفِ التطبيق (زر الرئيسية) ثم أظهره أثناء الجلسة —
   يجب أن تنجو الجلسة.

### ح. اختبار البطارية (المعيار 11)
1. سجّل نسبة البطارية، نفّذ جلسة 30 دقيقة، سجّل النسبة مجدداً.
2. العتبة: ≤ 12% استهلاكاً، ولا تحذير اختناق حراري في 15 دقيقة.

## 4. كيف تُسجَّل النتائج

1. **السجلات:** كل ملف JSONL مصدَّر يُحفظ مع ملف الحقيقة الأرضية
   المقابل (نفس `session_id`).
2. **التقييم الآلي:** لكل جلسة:
   ```sh
   python3 tools/score_sessions.py --log <session>.jsonl --truth <truth>.json
   ```
   يُلصق مخرجها في تقرير النتائج.
3. **تقرير النتائج:** ملف `POC_RESULTS_YYYY-MM-DD.md` يُحفظ في مستودع
   **Tilawa-PoC** (في جذر المستودع أو في `docs/`) ويحتوي:
   - جدول المعايير الـ 14 (القيمة المقيسة مقابل العتبة، ناجح/فاشل)،
   - نتائج `score_sessions.py` لكل جلسة،
   - سجلات JSONL مرفقة + لقطات شاشة للواجهة،
   - الخلفية المقيسة (`backend`: wasm/webgpu/cpu) وحجم WASM الفعلي،
   - قرار GO/NO-GO مع سببه.
4. يُرفع التقرير إلى مستودع Tilawa-PoC للمراجعة قبل أي قرار دمج — **لا دمج
   في التطبيق الرئيسي قبل GO موثَّق**. لا يُفتح طلب سحب (PR) على مستودع
   Tilawa أو Tilawa-Pro إطلاقاً.

### ما يُدوَّن في كل جلسة (قالب التسجيل — انسخه لكل جلسة من الـ 30)

| الحقل | ما يُدوَّن |
|---|---|
| `session_id` | اسم ملف JSONL المصدَّر (مثال: `poc-173...`) — نفسه في ملف الحقيقة الأرضية |
| المقطع | الفاتحة / آية الكرسي / الإخلاص / الملك 1–5 |
| نوع الجلسة | صحيحة / محذوفة / مستبدلة / زائدة / تردد-سلبي / متشابهات |
| الظروف | هادئة / ضوضاء (مروحة/تلفاز) — السرعة: بطيئة / عادية / حدر |
| الأخطاء المزروعة | عددها ومواضعها (`سورة:آية:كلمة` + الفئة) من النص المطبوع |
| الأخطاء المؤكدة | ما ظهر على الشاشة كـ «خطأ مؤكد» (الفئة + الموضع لكل واحد) |
| الإنذارات الكاذبة | كل خطأ مؤكد بلا خطأ مزروع مطابق |
| «غير متأكد» | عدد مرات ظهورها |
| زمن أول تظليل | تقديرياً بالثواني (أو من السجل لاحقاً) |
| زمن تأكيد الخطأ | بساعة الإيقاف: من نطق الكلمة الخاطئة إلى ظهور التأكيد (لكل خطأ مزروع) |
| زمن تحميل النموذج | الظاهر في الشاشة عند بدء الجلسة (للتحميل البارد فقط) |
| الخلفية `backend` | wasm / webgpu / cpu (من بطاقة الجلسة أو السجل) |
| ملاحظات | أي تعطل / تجميد / صمت / سلوك غريب — بنصه كما ظهر |
