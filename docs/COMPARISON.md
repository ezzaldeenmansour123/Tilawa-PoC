# مقارنة البدائل — قبل أي قرار دمج

**القاعدة:** لا قرار دمج نهائي في هذه الجولة. هذا الجدول توصية أولية فقط،
تُحسم بعد نتائج PoC على S22 Ultra. كل خلية «غير مقيس» تعني: لم يُقَس بعد،
لا تُقرأ كصفر ولا كنجاح.

## 1. خيارات تشغيل yazinsai/tilawa نفسها

| البعد | (أ) WebView تستضيف `@tilawa/core/web` — **خيار PoC الحالي** | (ب) إعادة تنفيذ Dart عبر ONNX | (ج) React Native التجريبي |
|---|---|---|---|
| الجدوى | الأعلى فوراً — الكود الأصلي دون نقل | ممكنة — المحرك TS بلا اعتماديات، والنموذج ONNX قياسي | الأضعف — المسار نفسه غير مُتحقَّق على الأجهزة |
| الجهد | 1–2 أسبوع | 4–6 أسابيع (نقل Zipformer المتدفق + CTC + محاذاة + فاحص) | 3–4 أسابيع + صيانة دائمة لقاعدة كود ثانية |
| الأداء/الاستجابة | **الخطر الأكبر**: WASM أحادي الخيط (بلا SharedArrayBuffer في WebView)؛ WebGPU غير مؤكدة | **الأفضل نظرياً**: ORT C++ أصلي + إمكانية NNAPI؛ بلا WASM ولا WebView | غير مقيس؛ Hermes + ORT-RN + BigInt غير مُتحقَّقة |
| الذاكرة | مضاعفة: WebView + JS + WASM + النموذج إضافةً إلى Flutter | عملية واحدة — الأقل المتوقع | عمليتا JS + أصلي؛ مشابه لـ (أ) أو أسوأ |
| الميكروفون | بشروط: إذن RECORD_AUDIO + منح WebChromeClient + سياق آمن (localhost) | الأنظف: التقاط أصلي PCM 16 kHz مباشرة | أصلي عبر مكتبة RN |
| دون إنترنت | فقط بالاستضافة الذاتية (assetBase/wasmPaths) | أصالةً: ملف محلي | ملف محلي |
| الترخيص | MIT + CC BY 4.0 (1.x فقط) + النِّسَب — نفسه في الثلاثة | نفسه + ORT MIT | نفسه + onnxruntime-react-native MIT |
| **الحكم** | **ابدأ به** (هذا PoC) | **الخطة ب** إن فشل (أ) أداءً فقط مع بقاء الدقة مقبولة | **مستبعَد** ما لم يقرر المستخدم تطبيقاً ثانياً |

## 2. البديل إن فشل yazinsai: Tarteel Whisper + sherpa-onnx

| البعد | yazinsai 1.x (WebView) | Tarteel Whisper + sherpa-onnx |
|---|---|---|
| النموذج | `spliced-clean-lite@1-int8` / `spliced-clean@1-int8` (Zipformer2-CTC متدفق) | `tarteel-ai/whisper-base-ar-quran` (Whisper مضبوط قرآنياً) أو tiny |
| ترخيص النموذج | **CC BY 4.0** — تجاري مسموح، شرطه النسبة (موثَّق من بطاقة النموذج وNOTICE.md — انظر `NOTICE.md`) | **Apache-2.0** — موثَّق في بطاقة النموذج ومصادر مستقلة عدة (جدول quran_android #3557؛ صفحات HF)؛ **يُعاد التحقق من بطاقة النموذج على Hugging Face قبل أي دمج** |
| ترخيص التشغيل | onnxruntime-web (MIT) | **sherpa-onnx (Apache-2.0)** — مستودع k2-fsa؛ حزمة `sherpa_onnx` على pub.dev تدعم Flutter arm64 على Android رسمياً (مقروءة اليوم من pub.dev)، مع VAD ومحاذاة قسرية (forced alignment — طوابع زمنية للكلمات) |
| الحجم | **lite 24.7 MB** / full 67.8 MB + مرجع 4.7 MB (+ WASM غير مقيس بعد) | tiny ≈ **65 MB** (WER ≈ 7.05%)؛ base ≈ **170 MB** (WER ≈ 5.75%)؛ نسخة int8 مدمجة من shahlarious ≈ 81 MB للـ base — كلها أكبر من lite |
| دون إنترنت | نعم (بعد التنزيل الأول، استضافة ذاتية) | نعم (بعد تنزيل النموذج؛ sherpa-onnx يعمل دون إنترنت أصلاً) |
| الدقة (معلنة، لا تُقارن مباشرة) | دقة 90.3% / التقاط 87.5% على صوت متعلمين (سطح مكتب M4)؛ PER 4.82% | WER ≈ 5.75% (base) / 7.05% (tiny) على التلاوة؛ دقة تحديد الآية (top-1) في قياس مستقل: base ≈ 83.7% مقابل fastconformer ≈ 89.9% — **ليست نفس مقاييس yazinsai، فلا تُقارن رقمياً قبل PoC خاص به** |
| التتبع | **متدفق لحظياً كلمةً بكلمة** (تظليل أثناء التلاوة + تأكيد بعد الكلمة التالية) | **ليس متدفقاً لحظياً**: Whisper يفكّ الشفرة على مقاطع (نوافذ/VAD) فالتغذية الراجعة تأتي بعد كل مقطع (ثوانٍ) لا كلمةً بكلمة؛ الطوابع الزمنية للكلمات في sherpa-onnx **تحتاج تحققاً** (الاحتياطي الآمن: تغذية على مستوى الآية/المقطع) |
| كشف الأخطاء | مدمج في المحرك: 4 فئات (خاطئ/محذوف/زائد/متخطَّى) + `suspected/confirmed/resolved/uncertain` | **غير مدمج**: يلزم منطق مطابقة فوق النسخ (المرجع: مشروع IqraAI، MIT — نسخ بـ Whisper ثم مطابقة وكشف أخطاء أخضر/أحمر/أصفر؛ تطبيق ويب Gradio ≈500 MB، مرجع منطق فقط، لا يُدمج كما هو) |
| نضج Flutter | لا مسار رسمي إطلاقاً (ويب/Node/RN تجريبي) — هذا PoC يختبر WebView | **ناضج**: حزمة Flutter رسمية + تطبيقات تجريبية (VAD من الميكروفون + ASR) + APKs جاهزة للتجربة |
| الجهد التقديري لـ PoC خاص به | 1–2 أسبوع (هذا المشروع) | 2–3 أسابيع (تطبيق PoC ثانٍ: نموذج + VAD + مطابقة + نفس مصفوفة القياس) |

## 3. بديل ثانٍ يُذكر ولا يُعتمد بعد

**`mohammed/fastconformer-quran-ar`** — FastConformer مضبوط قرآنياً،
**CC-BY-4.0**، قادر على البث حسب بحث مستقل موثَّق — لكن توافقه مع
sherpa-onnx وحجمه الدقيق ودقته على صوت متعلمين **لم تُتحقَّق**. يُدرس
فقط إن فشل البديل الأول (Tarteel Whisper).

## 4. مستبعَد صراحةً

**`Muno459/fastconformer-quran`** وكل أصل Quran-Lab — ترخيص **NPL-1.1/1.2
غير تجاري** (موثَّق في بطاقة النموذج على HF)، وقرار المستخدم المعتمد
يستبعد أصول Quran-Lab/0.x. لا يُستخدم ولو كانت دقته أعلى (5.41% WER
معلنة). أي تبديل إليه = BLOCKED.

## 5. التوصية الأولية (لا قرار نهائي)

1. **أكمل PoC الحالي (أ) أولاً** — هو أرخص اختبار يجيب: هل يعمل التتبع
   اللحظي على الهاتف أصلاً؟
2. **إن نجح (أ) بـ GO موثَّق:** ادمج yazinsai 1.x (lite أولاً) خلف واجهة
   `SpeechEngine`، مع بقاء البديل ممكناً دون إعادة كتابة الواجهة.
3. **إن فشل (أ) في الأداء/الاستجابة فقط مع بقاء الدقة مقبولة:** انتقل إلى
   الخطة (ب) — إعادة تنفيذ Dart عبر ONNX — قبل التفكير في تبديل المحرك.
4. **إن فشل yazinsai نفسه (دقة/التقاط/استقرار):** ابنِ PoC ثانياً منفصلاً
   لـ Tarteel Whisper + sherpa-onnx بنفس مصفوفة القياس (30 جلسة)، وقارن
   على الأرقام نفسها — مع قبول أن التغذية الراجعة ستكون على مستوى
   المقطع لا الكلمة، وأن منطق كشف الأخطاء يُبنى من الصفر.
5. **لا يُتخذ قرار دمج لأي خيار قبل GO موثَّق على S22 Ultra + مراجعة
   ترخيص نهائية** (إعادة قراءة بطاقة نموذج Tarteel على HF إن كان هو
   الخيار).
