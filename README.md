# Tilawa PoC — التسميع الذكي (مشروع تجريبي منفصل)

**الحالة:** مشروع تجريبي منفصل تماماً عن تطبيق Tilawa الرئيسي — لا يمسّ كوده ولا مستودعه.
**التاريخ:** 2026-11-25 — **الإصدار:** `poc-0.1.0` (إعداد أولي، لم يُبنَ APK بعد، لم يُختبَر على جهاز)

## الفكرة في سطر

تطبيق Flutter مستقل (`com.tilawa.app.tilawa_poc`) يضم WebView تستضيف محرك
`@tilawa/core/web` الإصدار `1.0.0-rc.1` من `yazinsai/tilawa`، مع النموذج
والمرجع وملفات WASM **مستضافة ذاتياً على الجهاز** (خادم `http://127.0.0.1`
داخل التطبيق — لأن ملفات الأصول ليست سياقاً آمناً، والميكروفون يتطلب سياقاً
آمناً)، ويقيس على هاتف حقيقي: زمن تظليل الكلمة، زمن تأكيد الخطأ، الدقة،
الذاكرة، والحجم — دون إنترنت بعد التنزيل الأول.

## ما هو موجود هنا

| المسار | الوظيفة |
|---|---|
| `lib/speech_engine.dart` | الواجهة المجردة `SpeechEngine` — نفس الواجهة التي سيستخدمها التطبيق الرئيسي لاحقاً إن نجح PoC، خلفها محوّل WebView (والخطة ب: محوّل Dart/ONNX أو sherpa-onnx) |
| `lib/webview_engine.dart` | محوّل WebView: يبني الجسر JS↔Dart ويحوّل أحداث `capabilities`/`position`/`checker` إلى أحداث Dart |
| `lib/local_server.dart` | خادم localhost (`dart:io` HttpServer) يقدّم الحزمة والنماذج من القرص — السياق الآمن للميكروفون |
| `lib/model_manager.dart` | تنزيل النموذج (lite أولاً) + `ref-v2.json` من `tilawa.dev/v1/` مع تحقق SHA-256، وحالة التثبيت |
| `lib/event_log.dart` | سجل أحداث JSONL محلي لكل جلسة (قابل للتصدير، لا رفع) |
| `lib/main.dart` + `lib/screens/` | شاشات PoC: التسميع، حالة النموذج، القياسات، السجلات |
| `web/` | حزمة JS: `src/bridge.js` يستورد `@tilawa/core/web`؛ يُبنى بـ esbuild إلى `assets/web/bundle.js` |
| `assets/web/tilawa.html` | صفحة WebView (تحمّل `bundle.js` من الخادم المحلي) |
| `tools/download_assets.py` | تنزيل الأصول مع تحقق SHA-256 (يُشغَّل في CI وفي أي جهاز بناء) |
| `tools/check_ref_schema.py` | يتحقق أن `ref-v2.json` فيه 6236 آية وأن كل آية فيها كلمات `w` (مصدر نص المقطع في الواجهة) |
| `tools/score_sessions.py` | يحسب الدقة/الالتقاط/زمن التظليل/زمن التأكيد من سجلات JSONL + ملف حقيقة أرضية |
| `test/` | اختبارات Dart للمنطق النقي (سجل الأحداث + استخراج كلمات المقطع) — تُشغَّل في CI |
| `.github/workflows/poc.yml` | CI: بناء الحزمة + `flutter analyze` + `flutter test` + بناء APK + إصدار `poc-N` |
| `docs/` | خطة القياس، بروتوكول اختبار الهاتف، مقارنة البدائل |
| `NOTICE.md` | النِّسَب والتراخيص حرفياً (MIT + CC BY 4.0 + شروط الاستخدام) |

## ما لم يُنفَّذ / لم يُختبَر بعد (بصراحة)

- **لا Flutter SDK في بيئة الإعداد** (`which flutter` → غير موجود): لم يُشغَّل
  `flutter analyze` ولا `flutter test` ولا `flutter build apk` هنا إطلاقاً.
  أول تشغيل لها يكون في GitHub Actions عبر `poc.yml`.
- **لم يُختبَر على جهاز**: لا S22 Ultra ولا أي أندرويد. أكبر مجهولين ما زالا
  مجهولين: (1) منح إذن الميكروفون داخل WebView، (2) توفّر WebGPU في WebView
  وأداء WASM متعدد الخيوط عبر العزل (COOP+COEP) — أُصلح في poc-10 بعد أن
  رجع `ort-wasm-simd.wasm` بـ 404 في poc-9؛ يُختبَر على الهاتف.
- **لم يُشغَّل المحرك استدلالياً في هذه البيئة**: نُزِّل النموذج lite والمرجع
  مؤقتاً للتحقق من البصمات والمخطط فقط، ثم حُذفا؛ لا يُشغَّل أي استدلال هنا.
- **لا APK ولا إصدار ولا دفع**: هذا المشروع محلي فقط في `~/workspace/tilawa-poc/`.
  البناء والنشر يتم لاحقاً بقرار المستخدم عبر `poc.yml` (يُنشر APK كإصدار
  `poc-N` في مستودع **Tilawa-PoC المنفصل** — `github.com/ezzaldeenmansour123/Tilawa-PoC` —
  لا يمسّ التطبيق الرئيسي ولا مستودعه إطلاقاً).

## البناء (عندما يقرر المستخدم — الخطوات موثقة فقط هنا)

```sh
# 1. بناء حزمة الويب (تحتاج Node 20+)
# `npm install` لا `npm ci` في المرة الأولى: لا يوجد package-lock.json بعد —
# يُثبَّت (commit) بعد أول بناء أخضر في CI (انظر .github/workflows/poc.yml).
cd web && npm install && npm run build   # ينتج assets/web/bundle.js

# 2. تنزيل الأصول والتحقق منها (lite افتراضياً؛ --tier full للكامل)
python3 tools/download_assets.py --tier lite --out assets/models
python3 tools/check_ref_schema.py assets/models/ref-v2.json

# 3. بناء APK (يحتاج Flutter 3.50.1 — كما في Tilawa)
flutter create --platforms=android --org com.tilawa.app --project-name tilawa_poc .
flutter pub get
flutter analyze && flutter test
flutter build apk --release --split-per-abi   # arm64 فقط للاختبار
```

أو تلقائياً عبر GitHub Actions: `.github/workflows/poc.yml` (يُشغَّل يدوياً
`workflow_dispatch` فقط — لا يعمل على كل دفع).

## معايير النجاح (من `docs/MEASUREMENT_PLAN.md` — مختصر)

| المعيار | قبول (GO) | رفض (NO-GO) |
|---|---|---|
| وسيط زمن تظليل الكلمة | ≤ 1.5 ث (P90 ≤ 2.5 ث) | وسيط > 2.5 ث |
| زمن تأكيد الخطأ | ≤ 5 ث | > 8 ث |
| تحديد الآية الصحيحة خلال 5 ث | ≥ 85% | < 85% |
| دقة كشف الأخطاء / التقاطها | ≥ 85% / ≥ 80% | < 80% / < 75% |
| إنذارات كاذبة | ≤ 1 / 5 دقائق | > 2 / 5 دقائق |
| زيادة الذاكرة RSS | lite ≤ 400 MB، full ≤ 700 MB، صفر OOM | تجاوز أو قتل |
| تحميل النموذج (بارد) | lite ≤ 15 ث، full ≤ 30 ث | تجاوز |
| دون إنترنت | جلسة كاملة في وضع الطيران، صفر طلبات شبكة | أي طلب أو فشل |
| البطارية | ≤ 12% / 30 دقيقة، لا اختناق حراري في 15 دقيقة | تجاوز |
| الميكروفون/الاستقرار | يعمل بعد المنح + رسالة واضحة عند الرفض؛ صفر تعطل في 20 جلسة | تعطل أو صمت |
| «غير متأكد» | ثقة < 0.6 أو `checker=uncertain` → «غير متأكد»، لا يُحسب خطأً | حكم قاطع بثقة منخفضة |

**قاعدة القرار:** تنجح PoC بتحقق كل المعايير الحرجة (التظليل، التأكيد،
الذاكرة، دون إنترنت، الميكروفون، الاستقرار) + 4 من 6 من الباقي. فشل حرج
واحد = NO-GO وانتقال للخيار التالي. **لا دمج في التطبيق الرئيسي إلا بعد
GO موثَّق على S22 Ultra.**
